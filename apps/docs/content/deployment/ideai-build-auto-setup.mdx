# IdeaI Build Auto-Setup System

**Last Updated**: January 1, 2026  
**Status**: Design Document  
**Version**: 1.0.0

## Overview

The IdeaI Build Auto-Setup System automates the complete setup of a new IdeaI project from scratch:
- ✅ Create GitHub repository
- ✅ Initialize project structure
- ✅ Create Vercel projects
- ✅ Configure DNS and domains
- ✅ Setup CI/CD workflows
- ✅ Verify and test deployment

**Goal**: One command to go from zero to fully deployed IdeaI project.

---

**Features**:
- Interactive CLI with prompts

- Quick setup mode
- Progress indicators
- Error handling

**Commands**:

### Phase 2: Project Generator

**Module**: `scripts/ideai-build/generator.mjs`

**Responsibilities**:
1. Create monorepo directory structure
2. Initialize Next.js apps with templates
3. Generate `.ideai.json` files
4. Setup `package.json` with dependencies
5. Create initial app files
6. Configure TypeScript and ESLint

**Process**:
```javascript
async function generateProject(config) {
  // 1. Create directory structure
  await createDirectories(config.project.name);
  
  // 2. Initialize each app
  for (const app of config.project.apps) {
    await initializeNextApp(app, config);
    await createIdeaiConfig(app, config);
    await setupDependencies(app, config);
  }
  
  // 3. Create shared packages
  await createSharedPackages(config);
  
  // 4. Create root files
  await createRootFiles(config);
  
  // 5. Initialize Git
  await initializeGit(config);
}
```

**Templates**:
- Next.js app template
- `.ideai.json` template
- `package.json` template
- TypeScript config template
- ESLint config template

### Phase 3: GitHub Integration

**Module**: `scripts/ideai-build/github.mjs`

**Dependencies**:
- `@octokit/rest` - GitHub API client

**Responsibilities**:
1. Create GitHub repository
2. Setup `.github/workflows` files
3. Configure GitHub Secrets
4. Initial commit and push
5. Setup branch protection rules

**Process**:
```javascript
async function setupGitHub(config) {
  // 1. Authenticate with GitHub
  const octokit = new Octokit({ auth: config.github.token });
  
  // 2. Create repository
  await octokit.repos.createForAuthenticatedUser({
    name: config.github.repo,
    private: config.github.private,
    auto_init: false,
  });
  
  // 3. Create workflow files
  await createWorkflowFiles(config);
  
  // 4. Setup secrets
  await setupSecrets(config);
  
  // 5. Initial commit
  await initialCommit(config);
  
  // 6. Setup branch protection
  await setupBranchProtection(config);
}
```

**Required GitHub Permissions**:
- `repo` - Full repository access
- `admin:repo_hook` - Repository hooks
- `admin:org_hook` - Organization hooks (if org)

**Secrets to Configure**:
- `VERCEL_TOKEN`
- `VERCEL_ORG_ID`
- `TURBO_TOKEN` (optional)
- `TURBO_TEAM` (optional)

---

### Phase 4: Vercel Integration

**Module**: `scripts/ideai-build/vercel.mjs`

**Dependencies**:
- `vercel` - Vercel CLI (or API client)

**Responsibilities**:
1. Create Vercel projects
2. Link projects to apps
3. Configure dashboard settings
4. Set environment variables
5. Setup domains

**Process**:
```javascript
async function setupVercel(config) {
  // 1. Authenticate with Vercel
  await vercelLogin(config.vercel.token);
  
  // 2. Create projects for each app
  for (const project of config.vercel.projects) {
    // Create project
    const projectId = await createVercelProject(project, config);
    
    // Link to app
    await linkVercelProject(project.app, projectId, config);
    
    // Configure dashboard settings
    await configureDashboardSettings(project, config);
    
    // Set environment variables
    await setEnvironmentVariables(project, config);
    
    // Setup domain (if provided)
    if (project.domain) {
      await setupDomain(project, config);
    }
  }
}
```

**Dashboard Settings to Configure**:
- Root Directory: `apps/{app-name}`
- Include files outside root directory: `true`
- Framework Preset: `nextjs`
- Build Command: `pnpm build`
- Install Command: `pnpm install`
- Output Directory: `.next`

**API Endpoints**:
- `POST /v9/projects` - Create project
- `PATCH /v9/projects/{id}` - Update project settings
- `POST /v9/projects/{id}/domains` - Add domain
- `POST /v10/projects/{id}/env` - Set environment variable

### Phase 5: DNS Integration

**Module**: `scripts/ideai-build/dns.mjs`

**Dependencies**:
- Provider-specific APIs (Cloudflare, AWS Route53, etc.)

**Responsibilities**:
1. Verify domain ownership
2. Create DNS records (CNAME, A, etc.)
3. Configure subdomains
4. Verify DNS propagation

**Supported Providers**:
- Cloudflare (primary)
- AWS Route53
- Google Cloud DNS
- Manual (instructions only)

**Process**:
```javascript
async function setupDNS(config) {
  // 1. Verify domain ownership
  await verifyDomainOwnership(config.dns.rootDomain, config);
  
  // 2. Create root domain DNS records
  if (config.dns.rootDomain) {
    await createDNSRecords(config.dns.rootDomain, config);
  }
  
  // 3. Create subdomain DNS records
  for (const subdomain of config.dns.subdomains) {
    await createSubdomainRecord(subdomain, config);
  }
  
  // 4. Verify DNS propagation
  await verifyDNSPropagation(config);
}
```

**DNS Records to Create**:
- CNAME: `{subdomain}` → `cname.vercel-dns.com`
- A: `@` → Vercel IP (if needed)
- CNAME: `www` → `cname.vercel-dns.com`

### Phase 6: Verification System

**Module**: `scripts/ideai-build/verify.mjs`

**Responsibilities**:
1. Build verification
2. Deployment testing
3. Health checks
4. Generate setup report

**Process**:
```javascript
async function verifySetup(config) {
  const report = {
    project: { status: 'pending', errors: [] },
    github: { status: 'pending', errors: [] },
    vercel: { status: 'pending', errors: [] },
    dns: { status: 'pending', errors: [] },
    deployment: { status: 'pending', errors: [] },
  };
  
  // 1. Verify project structure
  report.project = await verifyProjectStructure(config);
  
  // 2. Verify GitHub
  report.github = await verifyGitHubSetup(config);
  
  // 3. Verify Vercel
  report.vercel = await verifyVercelSetup(config);
  
  // 4. Verify DNS
  report.dns = await verifyDNS(config);
  
  // 5. Test deployment
  report.deployment = await testDeployment(config);
  
  // 6. Generate report
  await generateReport(report, config);
  
  return report;
}
```

**Checks**:
- ✅ Project structure exists
- ✅ All apps build successfully
- ✅ GitHub repository exists and accessible
- ✅ Workflows are configured
- ✅ Secrets are set
- ✅ Vercel projects exist and linked
- ✅ Dashboard settings correct
- ✅ Domains configured
- ✅ DNS records exist and resolve
- ✅ Deployments succeed
- ✅ Apps are accessible

## Usage Examples

### Example 1: Interactive Setup

```bash
node scripts/ideai-build.mjs setup
```

**Prompts**:
1. Project name?
2. Description?
3. Which apps to create? (web, docs, etc.)
4. GitHub organization?
5. Repository name?
6. Vercel organization ID?
7. Domain? (optional)
8. DNS provider? (optional)

### Example 2: Config File Setup

```bash
# Create config file
cat > setup.json << EOF
{
  "project": {
    "name": "my-project",
    "apps": ["web", "docs"]
  },
  "github": {
    "repo": "my-project"
  },
  "vercel": {
    "orgId": "team_xxx"
  }
}
EOF

# Run setup
node scripts/ideai-build.mjs setup --config setup.json
```

### Example 3: Quick Setup

```bash
node scripts/ideai-build.mjs setup --quick --name my-project
```

Uses sensible defaults:
- Apps: `["web"]`
- GitHub: Same as project name
- Vercel: Same as project name
- No domain/DNS

## Error Handling

### Error Types

1. **Configuration Errors**
   - Invalid config file
   - Missing required fields
   - Invalid values

2. **API Errors**
   - Authentication failures
   - Rate limiting
   - Network errors

3. **Setup Errors**
   - File system errors
   - Permission errors
   - Dependency errors

### Error Recovery

- **Checkpoint System**: Save progress at each step
- **Resume Capability**: Resume from last successful step
- **Rollback**: Undo changes on failure
- **Detailed Logging**: Log all operations for debugging

## Security Considerations

### Secrets Management

- ✅ Never commit secrets to repository
- ✅ Use environment variables
- ✅ Support `.env` files (gitignored)
- ✅ Prompt for secrets interactively
- ✅ Validate secrets before use

### API Tokens

- ✅ Store tokens securely
- ✅ Use minimal required permissions
- ✅ Rotate tokens regularly
- ✅ Log token usage (not values)

### Domain Verification

- ✅ Verify domain ownership before DNS changes
- ✅ Use secure DNS APIs
- ✅ Validate DNS records before deployment
